# Per-batch live monitoring transports

`tenant_admin` selects the live-monitor transport on each **regular** batch
that has an effective `local` or `s3` screen-recording mode. The selector is
stored as `batches.live_monitor_mode`:

| Value | Signaling | NAT relay |
| --- | --- | --- |
| `off` | None | None |
| `self_hosted` | E-PROC same-origin WebSocket | Optional tenant-owned coturn |
| `supabase` | Private Supabase Realtime channel | Optional Metered credentials |

The setting belongs to a batch, not to a browser. Only `tenant_admin` can change
it, and the API returns 409 once any candidate in that batch is `in_progress`.
That preserves the provider that the publisher and viewer use for the same
attempt. Practice and unrecorded batches cannot enable live monitoring.

## Privacy and scope

Both modes create a browser-to-browser WebRTC peer connection. E-PROC stores
only the viewer audit row (admin id, candidate id, batch id, hashed attempt id,
timestamps, and outcome). It never writes or operationally logs video, audio,
SDP, ICE candidates, signaling messages, realtime tokens, private keys, or API
keys.

Every session topic contains the trusted tenant slug, batch id, candidate id,
and a hash of the active JWT `jti`, avoiding numeric-id collisions between
tenants. A disabled or wrongly configured live provider must not stop an exam;
the student simply continues without a live viewer.

## Self-hosted mode

`self_hosted` keeps the existing short-lived HS256 token in
`Sec-WebSocket-Protocol` and E-PROC's `/api/live/signaling` endpoint. It retains
Origin, topic, actor, rate-limit, and heartbeat validation. Optional coturn
credentials are expiring HMAC values generated by E-PROC from
`LIVE_TURN_SHARED_SECRET`; the shared secret never reaches a browser.

See [live-monitoring-self-hosted-webrtc.md](live-monitoring-self-hosted-webrtc.md)
for coturn, TLS, IPv6, and AWS security-group configuration.

## Supabase Realtime + Metered mode

The historic third-party mode is intentionally explicit. It uses private
Supabase Realtime Broadcast channels for signaling and may obtain short-lived
TURN credentials from Metered. The browser receives the public Supabase URL/key
and a ten-minute ES256 realtime token; it never receives the Supabase private
signing key or Metered API key.

Run `migrations/20260905_live_monitoring_supabase.sql` in the chosen Supabase
project so private channels authorize the `live_topic` and `live_actor` claims.
Disable Supabase Realtime public access. Store real values only in the protected
application environment or managed secret:

```dotenv
LIVE_MONITORING_ENABLED=true
SUPABASE_URL=https://<project-ref>.supabase.co
SUPABASE_PUBLISHABLE_KEY=<set-locally>
SUPABASE_REALTIME_PRIVATE_KEY_BASE64=<set-locally>
SUPABASE_REALTIME_JWT_KEY_ID=<set-locally>
OPEN_RELAY_CREDENTIALS_URL=https://<application>.metered.live/api/v1/turn/credentials
OPEN_RELAY_API_KEY=<set-locally>
```

`OPEN_RELAY_*` is optional. If it is absent or Metered fails, this mode supplies
only Metered STUN servers and can still connect directly where the network
permits. E-PROC accepts only `https` relay credential URLs whose hostname ends
in `.metered.live`; it does not substitute an arbitrary public TURN endpoint.

## Operator check

1. Create a regular recorded batch and choose the intended transport.
2. Start a candidate's attempt, then open **Live** as a `tenant_admin`.
3. Confirm the candidate/admin sessions report the same `transport`, topic scope,
   and expected direct/relay result in the browser.
4. Confirm API rejection for Practice, a recording mode of `none`, regular
   `admin`, superadmin, inactive attempts, and a provider change during an
   active attempt.
